# 一张统一临床地图：最终普通中文说明

机器可复核的最终证据总表是 `research/unified_map/FINAL_EVIDENCE.json`，root 为
`sha256:54106a834a6343574381407a2c080db32349ad722e72a57acc0af95bfc3e8b04`。

## 先说结论

我们确实做出了“同一份患者状态同时回答诊断、未来、不同治疗结果，并能随着新观察
继续更新”的模型，也用第二套独立代码逐值复现了最深度研究的 F18。但是：

> 找到了固定合成目录内有用的共享状态；没有找到通过完整硬门槛的 Unified Clinical
> Map。开放世界统一状态尚未建立，也没有证明它永远不可能存在。

三个跑满 W01--W20 和五组随机种子的普通候选都把一些未知机制不安全地硬认成已知：
F10 有 5 次，F14 有 21 次，F18 有 5 次。因此正式合格候选是 0，主 Pareto 前沿为空。
F18 的声明上限只是 `L2-RUNNABLE`，不是 benchmark 通过者。

所有证据都来自合成世界；不代表真实临床有效、生产安全或全局最优。

## 我们真正测试的是什么

系统先把当前时刻以前已经可见的病历折叠成一份状态：

```text
过去的可见病历 -> 一份患者状态 Z
                    ├─ 诊断
                    ├─ 不新增治疗会怎样
                    ├─ 治疗 A 会怎样
                    ├─ 治疗 B 会怎样
                    ├─ 治疗 C 会怎样
                    └─ 新结果回来后更新成下一份 Z
```

关键不在于接口都叫 `state`，而在于这些问题真的只能读取同一份不可变状态。诊断不
能藏一份患者记忆，治疗再藏另一份；回答问题时也不能偷偷重读完整病历、未来信息或
模拟器真状态。

如果两段病历被压成同一个状态，但一种治疗对前者有益、对后者有害，这叫“危险碰
撞”，必须硬淘汰。相反，如果两段病历对所有允许的未来都一样，状态却把它们分得很
远，这叫“虚假拆分”，说明地图还不够简洁。

## 冻结题目和实验账本

W01--W20 是 20 个有完整反事实答案的合成小世界，共 21 个 panel。它们覆盖部分可见、
同表现不同病程、同自然病程不同治疗反应、延迟检查、路径依赖、共源观察、隐藏混杂、
新检查、新治疗、未知机制、罕见禁忌等问题。

生成器、oracle、M01--M16 指标和五组随机种子承诺先冻结，冻结根为：

```text

```

机器实验索引的最终账是：

```text
总条目                 38
可计入实质实验         30
不可计入               8
失败尝试               1
证据缺口               0
```

EXP-037 是 F22-v1 的失败尝试，不计数。EXP-038 是修复后真正跑完的 F22-v2，算一个
实质实验，但它出现 1 个危险碰撞和 1 个不安全 OOD，所以按预注册规则 **ABANDON**。
“算实验”不等于“模型合格”。

## 跑满的三个候选

F10、F14、F18 都跑了全部 W01--W20、五组随机种子，每个正式结果有 1,680 个测试
episode：

| 候选 | 主要描述性优点 | 不安全 OOD | 正式判决 |
|---|---|---:|---|
| F10 | 较小、治疗 regret 较低 | 5 | 硬失败 |
| F14 | lifted dynamics 预测较好 | 21 | 硬失败 |
| F18 | 三者中自然/治疗轨迹误差较低 | 5 | 硬失败；封印研究对象 |

平均预测再好也不能抵消把未知机制自信塞进已知类别，所以没有主 winner。

## F18 到底是什么

F18 把公开病历按可获得时间递推折叠，保留：

1. 观察的近期值、均值、斜率和次数；
2. 检查、治疗和事件次序的短期/长期递推记忆；
3. “诊断 + 所有目录内治疗未来”形成的行为类别概率；
4. 连续动力学坐标和当前历史离训练支持范围有多远。

诊断和每个治疗预测都只读取这一份状态。闭环演示里，更新前所有头读取同一个 hash：

```text
sha256:1282d5968795563ce3462df506842ad6a2acc2ad0386abf699c1a7b0f4b3a352
```

模型按自己的预测选择治疗，新的公开结果回来后用同一个更新入口得到：

```text
sha256:87503e34df85a56b122b53a1d7b2015095f0a28a73a30d2c5622283e3f486b28
```

这证明“一份状态扇出再更新”真的运行了；它不证明答案正确。

## 独立复现证明了什么

第二套实现没有 import 原候选代码，独立重写病历折叠、状态格式、拟合和读出。完整复现
路径是：

```text
results/unified_map/reproduction/
  20260719T101913Z-I18-full-repro-01c908cb1b
```

它覆盖 1,680 个 episode、28,720 次 rollout query、260 个主作用域配对探针和五组
随机种子。W16/W17 的 `S1` 扩展配对按冻结 runner 的规则留给单独 extension reveal。
所有记录的最大差异都是 0，failure 计数也是 0。

这只说明独立实现和封印 F18 做了同一件事；它没有重新计算 oracle 指标，也不会把
F18 的 5 次 OOD 失败变没。

## 为什么小型确认不能推翻完整失败

另有一个承诺后揭示的 `CONFIRM5 lite`：全部世界、五组种子，但每个 panel/seed 只有
train 4、validation 1、test 2，并且 pair probe 是 0。F10 和 F18 在这个小样本上
通过；F14 有 9 次不安全 OOD，B02V2 有 10 次。B03V2 虽然部分计数好看，却是三套
任务状态，按定义不合格。

在这个**仅限小样本且没有碰撞证据**的局部观察里，F10 更小更快，F18 的动力学误差
和 regret 更低，两者互不支配。它不能覆盖三个完整正式 run 的硬失败。

## 正式红队 v2 得到了什么

正式 source-distinct 红队包是：

```text
20260719T093209Z-RT2-6337a6ad2d
sha256:d3b0ecfd8722e9863d84d3bd88ffa30d9e00b04976ac48b50cd00f02f34040b3
```

封印 F18 和独立 I18 都只打开一次承诺包。结果必须分开解释：

- **固定目录内局部支持：** 16 个 OOD 行里不安全强认是 0；8 个配对行里危险碰撞是
  0；已知治疗查询只读同一状态且不改状态。
- **开放世界失败：** 对没见过的新检查和“反向反应”的新治疗，模型会安全拒答；但
  真要支持它们，仍要重新拟合扩展模型并回放可见历史。安全拒答不等于已经会用。
- **新非线性组合是混合结果：** 固定目录内的自然病程还能回答，扩展检查一半仍然
  scope insufficient；又没有预注册准确率门，不能把它说成组合泛化通过。
- **新任务未知：** 容量对照数字只是描述，没有预注册判定阈值，结论是
  `INCONCLUSIVE`。
- **最小性不成立：** 四个 oracle 认为等价的历史删除对照都被 F18 分开，因此没有
  证据说它是最小行为地图。

这里的 0/16 和 0/8 只支持这个承诺包内的局部行为，不能抵消完整 benchmark 的 5 次
OOD 硬失败。

## 次级指标能说什么

次级 battery 明确标为 exploratory，不是冻结正式指标：

- M09 的描述性前五顺序是 F16、F10、F14、F22、F18；
- M11 中 F10/F14/F18/F22 对新检查/治疗都 scope insufficient；每个 family 的两个
  探针各自合计回放 3,396 字节；
- M13 的 Python `tracemalloc` 平均峰值增量约为 F22 49.0 KB、F10 49.7 KB、
  F18 191 KB、F14 399 KB；它不保证覆盖 native allocator；
- M16 会随 family、容量和读出视角改变排序，所以不能证明状态充分。

这些数字用于定位下一步，不能制造 winner。

## 最终四类结论

### 已验证

- benchmark/oracle/种子冻结和证据 custody；
- 38 条记录、30 个实质实验的机器账本；
- 三个候选跑满全部世界和五组种子；
- 一份状态真正服务诊断、自然病程、治疗反事实和更新；
- 独立实现对 F18 的完整声明作用域逐值一致。

### 仅有合成局部支持

- 固定目录内，共享状态可以有用；
- CONFIRM5 lite 中 F10/F18 是两个互不支配的局部点；
- RT2 这个承诺包里，F18/I18 的 OOD、碰撞和已知动作行为没有出现硬失败。

### 已失败

- 所有完整普通候选的 OOD 硬门；
- F22-v2 的碰撞和 OOD 门；
- 新检查/新治疗不回放历史的本地扩展；
- F18 的最小状态主张。

### 仍未知

- 新任务是否能由某种更好共享状态支持；
- 一般有限或动态增长 UCM 是否存在；
- 真实患者上的识别、有效性、安全性和迁移；
- 全局最优架构。

## 下一步最高信息增益实验

不要继续在已弃用 F22 上事后打补丁。应预注册一个新版本/新架构，先封印源码，再用
新的 commitment/reveal 生成 source-distinct 测试包。它必须原生支持 `S1` 增量扩展：

- 故意藏起一个检查和一个治疗；
- 只允许“旧状态 + 扩展公开参数 + 新增可见 delta”细化状态；
- 禁止重拟合核心，禁止回放完整可见历史；
- 预先冻结非零的反向治疗/碰撞 pairs、OOD 零不安全硬门；
- 给新任务预先写数值阈值，并做同容量 state/full-history/true-state 对照；
- 同时测相关、无关、冗余历史删除，检查最小性；
- 与 F10、F18、B02V2、B03V2 在同一未打开测试包上比较。

这是最高信息增益，因为它正面测试当前唯一没有跨过去的边界：失败到底只是 F18/F22
把固定目录学得太死，还是当前观测制度本来就无法支持“不回放历史的开放世界状态”。
