# 从第一原理理解“一张统一的动态临床地图”

> 前述章节是在 benchmark 和候选实现前冻结的问题语义；第 21 节追加截至完整 benchmark、source-distinct RT2 与 full REPRO5 的经验答案。原始判据未因候选结果而修改。

## 1. 先问状态要保留什么，而不是它长什么样

截至时刻 `t`，系统只得到患者的可见历史：

```text
H_t = 按可获得时间截断的观察、检查、已实施动作及其条件
```

患者内部世界、未实施治疗的结果和未来观察不可直接读取。候选编码器只能计算：

```text
Z_t = phi(H_t)
```

`Z_t` 可以是有限向量、belief distribution、图、预测测试向量、程序或动态结构。形式不是定义；它是否保留了未来可区分行为才是定义。

## 2. 候选核心定义：受控未来行为等价

令 `Pi` 是当前允许的未来策略集合。一个策略可以根据随后看到的结果，自适应地选择等待、检查或治疗。令：

```text
P(. | H_t, do(pi))
```

表示从历史 `H_t` 出发，按策略 `pi` 实施动作后，未来潜在状态、可见观察、事件与结局的联合分布。

两段历史 `h` 与 `h'` 在动作/检查集合 `Pi` 和时间范围 `T` 下精确等价，当且仅当：

```text
h ~[Pi,T] h'
iff
对每个 pi in Pi，P(Y_future | h, do(pi)) = P(Y_future | h', do(pi))
```

这里的 `Y_future` 不能只选一个方便指标；它至少覆盖 benchmark 声明的状态、观察、事件和临床效用。策略包括 no-op，因此自然病程也是受控未来的一部分。

一个表示 `phi` 是预测—干预充分的，如果：

```text
phi(h) = phi(h')  =>  h ~[Pi,T] h'
```

如果反向也成立，即所有行为等价历史恰好落到同一状态，那么它还是相对于该范围的最小行为状态。最小指不做无用区分，不等于维度最少或文件最小。

这一定义是待实验攻击的重要候选原理，不是预先宣布的普遍定理。

## 3. 为什么它能把三个任务放在同一张地图上

若 `Z_t` 对受控未来充分，则：

- **诊断**：从 `Z_t` 读出与未来行为有关的机制/疾病/病程类型后验；
- **自然预测**：选择 `pi = no-op` 或当前治疗延续；
- **治疗预测**：把 `pi` 换成治疗 A/B/C 或动作序列；
- **更新**：实际动作和新观察到达后，用同一递推算子更新 `Z_t`。

诊断标签不是地图本体。若两个病名在全部允许检查、治疗和结局下完全不可区分，地图没有行为理由强行拆开；它应保留诊断不确定性。反过来，两个病名相同但治疗反应不同，也不能仅凭同名合并。

## 4. “可更新”是状态的必要条件

真正的递推状态必须存在统一更新算子 `U`：

```text
phi(H_t append e_{t+1}) = U(phi(H_t), e_{t+1})
```

其中 `e` 可以是已实施动作、检查结果或普通观察。左、右两边允许数值近似，但读出分布必须在预注册误差内一致。

如果每次治疗查询都重读完整病历并构造另一套表示，或者诊断头和治疗头各维护一份隐蔽 cache，就没有证明共享状态。完整历史可以作为显式无压缩状态基线，但必须承认其尺寸会增长，不能把它包装成紧凑地图。

## 5. 同一对象不等于同一语义

把三个模型的输入都命名为 `state`，或让它们共享一个 Python object，并不证明共享患者状态。硬性含义是：

1. 编码只使用截至当前可见的 `H_t`；
2. 三个任务头只读取同一份不可变 `state_id/state_hash/payload`；
3. 任务头不读取原始历史；
4. model parameters 可以任务不同，但不得包含该患者的任务专属 latent/cache；
5. 更新只从旧共享状态和新事件产生新共享状态；
6. 诊断、no-op、各治疗预测对状态含义的解释兼容。

不同读出头是允许的，因为问题不同；不同患者隐状态是不允许的。

## 6. 状态必须包括不确定性，而不是猜一个隐藏真值

部分可观察时，多种内部世界可能与同一历史一致。真实患者只有一个隐藏路径，但系统的可计算状态通常是对此路径/机制/个体参数的不确定分布。

因此，正确状态可能是：

- POMDP belief；
- 参数和状态的 posterior；
- 对未来受控测试的预测集合；
- 一组仍未区分的行为等价类及权重。

若两个患者历史完全相同、且现有检查无法辨别其隐藏类型，编码器把他们放进同一 belief state 并不构成碰撞；虚构个体真类型才是泄漏。只有当可见历史包含应保留的区分信息，或者两段不同历史被错误合并，才构成可归责的危险碰撞。

## 7. 观察过程和生理过程必须区分

一个动作可能：

1. 只改变内部状态转移；
2. 只改变观察通道；
3. 同时改变二者；
4. 改变未来可获得哪些检查。

退热药让体温下降不等于炎症消失；氧疗下的血氧与室内空气血氧不等价。共享状态若只追踪“当前观察值”，会把 W05–W07 中不同未来错误合并。

因此 `Z_t` 必须保留对未来行为有影响的：隐藏机制 belief、个体基线、既往动作暴露、观察条件、延迟队列和路径依赖量。它不必逐字段显式命名，但读出必须证明这些差异未丢失。

## 8. 关联未来和干预未来不是同一个分布

```text
P(Y | A=a, H_t) != P(Y | do(A=a), H_t)
```

除非额外识别条件成立。历史治疗往往由病情严重度决定；只学习接受某治疗者的结局会把选择偏差当治疗效果。

一个共享状态可以很好地预测观察性未来，却完全不够支持治疗决策。干预预测必须来自随机化、已知生成机制、有效工具变量或明确且可审计的因果识别假设。能运行 SCM/图/世界模型不等于干预效果已识别。

W15 专门把“高预测准确率但错误治疗方向”定义为硬失败。

## 9. 行为等价依赖范围，不存在脱离范围的绝对最小状态

等价关系至少依赖：

- 允许的检查集合；
- 允许的治疗/动作集合；
- 预测时间范围；
- 关心的结局与效用；
- 观察精度和可获得性；
- 宿主人群与机制支持域。

加入新检查可能把旧 belief 拆开；加入新治疗可能让旧时完全等价的历史变得治疗上不同；把范围从 1 小时延长到 7 天可能要求保留更慢的机制。

所以“最小 UCM”只能写成 `Z^[Pi,T,Y]`。W16、W17 和冻结后扩展实验不是边角功能，而是检验候选是否诚实表达适用范围、能否局部细化，或是否必须承认旧状态不再充分。

## 10. 精确状态可能存在的典型条件

以下只是存在性例子，不是架构选择：

- 已知有限 POMDP 中，隐藏状态 posterior belief 是受控预测充分统计量；
- 已知线性高斯系统中，filter mean/covariance 在模型条件下闭合；
- 有限线性维度的 controlled process 可能有有限秩 PSR；
- 有限 causal states 的过程可由其预测等价类表示；
- 完全可观察 Markov 系统的当前物理状态本身充分。

这些保证都依赖正确模型、动作范围和识别条件。有限个隐藏离散状态的 belief 仍是连续对象；“有限维”不等于“有限状态数”。

## 11. 精确有限状态可能不存在的原因

至少有五类反例：

1. **无限路径依赖**：下一步响应依赖完整的既往动作/观察序列，且不存在有限递推统计量；
2. **无限维 posterior**：未知非参数动力学或连续参数的 belief 无有限闭合族；
3. **持续新增动作/检查**：每个新 probe 都能拆分一个旧等价类，状态维度无稳定上界；
4. **任意长时间尺度**：新的慢变量不断变得与结局相关；
5. **非平稳世界**：生成规律本身无界漂移且缺少可学习的演化状态。

最小反例应展示：任意候选有限摘要都能找到两段被其合并的历史，而某允许策略使未来分布不同。仅说“医学很复杂”不是反例。

## 12. 近似状态应如何定义

现实候选通常只能近似。不能只用状态向量欧氏距离自证相似，而应按未来行为误差定义：

```text
d_behavior(h,h') = sup over pi in Pi of
  D(P(.|h,do(pi)), P(.|h',do(pi)))
```

`D` 可以是预注册的总变差、Wasserstein、轨迹误差或临床效用差。治疗安全还必须单独测：

```text
max_pi |U(h,pi)-U(h',pi)|
```

若两个近状态对最佳治疗方向相反且 regret 超门槛，这是危险碰撞，不能被平均预测分数掩盖。近似状态的声明必须带范围、误差界、最坏病例和置信区间。

## 13. 虚假拆分为什么也重要

若两段历史对所有允许策略产生同一未来分布，却被编码为远距离状态，通常不会直接造成治疗伤害，但说明表示：

- 保留了无关身份/时间/格式噪声；
- 样本效率差；
- 不容易组合或迁移；
- 可能只是记忆器。

因此 benchmark 同时测危险碰撞和虚假拆分。安全优先级不同，但二者共同决定是否接近“地图”而非病例索引。

## 14. 患者状态、世界模型参数和效用必须分开

- `Z_t`：这个患者截至当前的共享状态；
- `M`：跨患者学习的转移、观察和干预模型参数；
- `U_patient`：患者价值或固定 benchmark 效用；
- `head`：从 `Z_t` 与 `M` 计算某类答案的读出。

共享的是患者状态，不要求所有任务共用同一损失或输出层。效用改变治疗选择，但除非它改变患者生理动力学，否则不应偷偷写进患者状态。模型参数可以复杂，但不得把单个评估患者的第二 latent 藏在参数对象或全局 cache 中。

## 15. 多种数学表示可能是同一张行为地图

向量、belief、PSR、causal state、图或程序状态若存在保留更新和全部受控未来预测的双向变换，它们可能只是同一行为状态的不同坐标。

因此研究不以 class 名判定“真正不同”，而比较：

- 状态等价类是否相同；
- 更新是否闭合；
- 干预是否可组合；
- 学习和识别假设；
- 尺寸、样本和计算成本；
- 新动作/检查下是否局部扩展；
- 哪些反例能区分它们。

同一个数学对象换字段名不计一个新家族。

## 16. OOD 是地图边界，不是额外诊断标签

候选必须区分：

- 当前 belief 内仍有多个已知解释；
- 信息不足；
- 观察或动力学不在模型支持域；
- 新机制不能由现有状态和转移解释。

OOD 不是强行增加一个万能“其他病”类别。它至少应反映 predictive residual、support/evidence、epistemic uncertainty 或模型集合分歧，并在 W18 检验。高置信把未见机制塞进已知状态是硬失败。

## 17. 新读出是检验充分性的探针

冻结编码器后增加一个训练时未优化的新读出。如果该读出属于已冻结的未来行为/结局范围，却必须重读历史，说明旧状态丢了范围内信息。若新读出原本不属于范围，则失败说明范围需要扩张，而不是自动否定旧范围内充分性。

因此每个“新任务”实验必须先声明它是否在原 `Y` 闭包中，避免用无限任务要求制造不可证伪标准。

## 18. 从理论到可运行证据的声明阶梯

本研究只允许按以下阶梯逐级声称：

1. **可编码**：对象能表达例子；
2. **可运行**：能更新并输出三类任务；
3. **benchmark 支持**：冻结 W01–W20 上通过硬门；
4. **反例后支持**：candidate freeze 后 red-team 未推翻声明范围；
5. **独立实现支持**：第二实现复现核心结果；
6. **仅合成范围结论**：仍不等于临床有效、安全或全局最优。

任何候选在第 2 级成功都不能跳到第 6 级。

## 19. 可证伪的研究主假说

### H-UCM-1：局部共享状态存在

对冻结的有限动作、检查、时间和世界集合，存在比完整历史更紧凑的近似递推状态，在诊断、自然预测和治疗预测三项上无不可接受退化，并减少跨任务不一致或提高样本效率。

**推翻**：所有紧凑共享候选都发生危险碰撞，或被 separate-task baseline 严格支配；只有完整历史记忆器可通过。

### H-UCM-2：治疗充分性严格强于自然预测充分性

仅按 no-op 未来压缩的状态会在 W04/W17/W19 合并治疗反应不同的历史；纳入 controlled futures 后碰撞下降。

**推翻**：在公平容量和数据下，两种状态在所有治疗 probe 上等价，或差异来自泄漏/额外数据。

### H-UCM-3：有限固定状态不是全局保证

动作、检查或时间尺度扩张会使至少部分旧状态不再充分；诚实架构应局部细化或返回“不足”，而不是维持无条件充分主张。

**推翻**：一个固定有限状态在预注册的连续扩展序列上保持受控未来充分，并有可验证的闭包理由。

### H-UCM-4：行为状态可能有多种等价坐标

最强候选之间可能在行为预测上等价，但学习、简洁性和扩展成本形成 Pareto，而非唯一数据结构赢家。

**推翻**：冻结反例能稳定区分其中一个表示保留了另一表示无法恢复的受控未来信息。

## 20. 当前未知，不能在实验前写成结论

- 临床有用范围内是否存在足够低维的共享状态；
- belief/PSR/causal state/SCM/神经或机制图哪类更自然；
- 状态维度会否随动作目录、时间范围和机制数不可控增长；
- 从有限观察数据能否识别治疗效应而不依赖过强假设；
- 紧凑共享状态能否不牺牲罕见禁忌；
- 在真实临床数据上是否仍成立。

这些问题必须由冻结 benchmark、反例、独立实现和最终证据分区回答。

## 21. 执行后的第一原理答案

### 21.1 证据账本先于解释

```text
freeze root:
  sha256:8acb6623c2fdf79008240c5f5967b2143c4fb5e7bb87a4e8aa9f72e77ef33a2d
experiment index:
  38 total / 30 count-eligible / 8 ineligible / 1 failed attempt
complete ordinary runs:
  F10, F14, F18; each W01--W20 x R01--R05 x 1,680 rows
unsafe forced-known OOD:
  F10=5, F14=21, F18=5
```

所以 primary hard-gate-eligible set 和 formal Pareto set 都是空集。EXP-037
F22-v1 是不计数的失败尝试；EXP-038 F22-v2 虽然是 count-eligible 实质实验，却因
一个危险碰撞和一个 unsafe OOD 按预注册规则 `ABANDON`。实验数量不能替代证据门。

### 21.2 H-UCM-1：只得到固定目录内局部支持

F18 是有限递推共享状态，诊断、no-op、各治疗未来和 update 的确使用同一对象；
CONFIRM5 lite 中 F10/F18 也形成一个局部互不支配 trade-off。但三个 complete
candidate 都有 OOD 硬失败，所以任何普通候选都没有达到
`L3-BENCHMARK_SUPPORTED`。F18 的 UCM 声明上限是 `L2-RUNNABLE`。

因此得到支持的是：

```text
在固定合成 catalog 内，可以学习到有用的有限近似共享状态。
```

没有得到支持的是：

```text
存在已通过冻结全语义硬门的 learned UCM。
```

### 21.3 H-UCM-2：治疗索引未来和不确定性是必要信号

F21 把行为 posterior 压成单点后出现四个危险碰撞；CE-005 也说明只保留无序均值、
斜率和计数会抹掉受控未来所需的顺序/可获得性。平均诊断分或自然轨迹无法补偿这些
反例。当前合成证据直接支持：若状态身份忽略治疗索引未来、posterior uncertainty
或路径次序，它不可能满足声明的 controlled-future 范围。

这仍然是对已测试压缩方式的反例，不是“某种特定 posterior 坐标是唯一正确表示”
的定理。

### 21.4 H-UCM-3：作用域相对性得到正式 RT2 支持

source-distinct RT2 对 sealed F18 和 independent I18 给出：

- committed pack 内 OOD unsafe `0/16`、dangerous collision `0/8`，只属于
  `CLOSED_CATALOG_LOCAL_SUPPORT`；
- 新检查和反向反应新治疗全部会安全 abstain，但要真正支持它们，必须 extension fit
  并回放 visible history，判为 `OPEN_WORLD_SCOPE_FAILURE`；
- new nonlinear combination 只得到 fixed-catalog natural-query support 与
  extension-check failure 的 mixed 结果，没有预注册 accuracy pass rule；
- 四个 oracle-equivalent deletion controls 全被拆开，state minimality
  `NOT_SUPPORTED`；
- new-task capacity ladder 没有预注册裁决阈值，只能是 `INCONCLUSIVE`。

因此行为等价确实依赖允许的检查/动作集合；“安全拒答”证明边界诚实，却不证明旧
state 能局部吸收新 operator。它推翻 F18 的 once-for-all catalog 主张，但不证明所有
有限或动态增长状态都不可能。

### 21.5 H-UCM-4：只有局部 Pareto，没有等价坐标定理

complete F10/F14/F18 都因 noncompensating OOD 被 Pareto 前置硬门淘汰。一个更小的
CONFIRM5 lite（all worlds、five seeds、train4/val1/test2、pair0）里，F10 更小/更快，
F18 dynamics/regret 更好，二者互不支配；这个局部前沿没有 collision evidence，也
不能覆盖 complete run。

secondary battery 的 M09/M11/M13/M16 明确是 exploratory：它提供样本、扩展、内存
和 readout 线索，却没有证明候选间是同一最小行为状态的坐标变换，更不能建立 winner。

### 21.6 独立复现回答“实现相同”，不回答“架构正确”

full REPRO5 `20260719T101913Z-I18-full-repro-01c908cb1b` 覆盖 1,680 episodes、

### 21.7 最终最小诚实结论

```text
已验证：
  frozen finite simulator 的 privileged true state 有限且充分；
  learned recursive one-state fan-out/update 可以真实运行；
  I18 完整等价复现 sealed F18。

仅合成局部支持：
  固定 catalog 内有限近似共享状态有用；
  RT2 的有限 OOD/collision/known-action pack 无硬失败；
  pair-free lite 中 F10/F18 是局部互不支配点。

已失败：
  所有 complete ordinary candidate 的 OOD hard gate；
  F22-v2 的 collision/OOD；
  F18 对 unseen check/treatment 的 replay-free local refinement；
  F18 minimality claim。

尚未知：
  new-task sufficiency；
  一般有限或动态增长 UCM 是否存在；
  真实临床识别、有效性、安全性、迁移和全局最优。
```

### 21.8 下一项最高信息增益实验

预注册一个新 architecture/version，用 fresh source seal 和 commitment/reveal 打开一
个 source-distinct pack。它必须原生支持 `S1` 增量扩展：只允许旧 state、公开扩展
参数和新 visible delta，禁止 core refit 与完整 history replay；同时预先冻结 nonzero
opposite-response pairs、OOD zero-unsafe hard gate、new-task 数值阈值与同容量
state/history/true-state 对照，以及 relevant/irrelevant/redundant deletion controls。

这是最高信息增益，因为它直接区分两种仍开放的解释：F18/F22 只是 monolithic catalog
设计失败，或当前观察制度本身不能支持 replay-free open-world state refinement。
