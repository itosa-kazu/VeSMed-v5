# Primary real-case holdout execution protocol

Status: **FROZEN BEFORE PRIMARY CASE SEARCH OR SELECTION**  
Protocol: `NCF-PHEP-1.1.0`  
Architecture: `NCF-ARCH-1.0.0`  
Gate contract: `NCF-PLG-1.1.0`

This protocol closes the gap between a case-blind structural runtime and the
claim that a **complex real longitudinal case was correctly represented,
localized and recursively updated**.  It is independent of VeSMed V5.  The
normative machine contract is `PRIMARY_HOLDOUT_EXECUTION_PROTOCOL_v1.json`.

## 1. What this run may establish

A passing run may establish only that the frozen NCF implementation can express
and update this selected case within the frozen adult-ICU acute-hemodynamic-
collapse scope.  It cannot establish calibration, population validity,
clinical utility, or a true untreated individual counterfactual.

The real-case claim is not rescued by structural toy probes.  The selected case
itself must exercise longitudinal updating, concurrent process representation,
at least two local organ/process domains, delayed information and an observed
action lifecycle.  If it does not, the run is `HARNESS_INCOMPLETE` for the
question being asked even when all case-independent gates pass.

## 2. Deterministic case discovery and selection

The scout receives only this protocol, the identifier-only exclusions, the
combined pre-primary seal and the broad scope statement.  It must not read the
model pack, model node registry, runtime code/output, likelihoods, oracle or
expected diagnosis.

Two frozen PubMed searches are executed exactly as recorded in the JSON
contract, with the declared sort and retrieval limit.  The complete identifier
result snapshot is stored before eligibility screening.  Manual replacement,
extra search terms or skipping an eligible article is forbidden.

Each query run must preserve the untouched PubMed ESearch HTTP response bytes
under `holdout/evidence/primary_search_raw/payloads/`, with path, byte count and
SHA-256.  The request URL is canonical: exact NCBI HTTPS endpoint, fixed
parameter order, and RFC3986 percent encoding recomputed from frozen Q1/Q2
parameters.  The offline frozen `compile_primary_search_snapshot.py` consumes
only those exact bytes plus the retrieval manifest and deterministically emits
two capture manifests and the complete snapshot; it has no network access.

Before screening or selection, `validate_primary_search_snapshot.py` reopens
the exact payload bytes, verifies URL/request identity, first-page completeness,
`retrieved_count == len(idlist)`, and the exact ordered `PMID:<id>` projection.
The screening universe must equal the compiler's canonical identifier union.
A missing, substituted, duplicated, unhashed or incomplete response is
`HARNESS_INCOMPLETE`, not a selectable pool.

Every screening disposition is separately checked by the frozen offline
`validate_primary_case_screening.py`.  Its evidence index binds the exact
protocol, search snapshot, screening manifest and exclusions; every candidate
and every true or false criterion binds one immutable source snapshot plus a
precise byte locator.  NCBI-backed PMID/PMCID/DOI identity aliases are
content-addressed so exclusion and duplicate-article checks are recomputed
rather than trusted from screening booleans.  The validator, its test source,
and `primary_screening_evidence.schema.json` are pre-primary-bound assets.

Eligibility is diagnosis- and model-neutral.  The report must be a single-adult
open-full-text primary case with acute ICU-level hemodynamic collapse and enough
reported chronology to support all of the following without invented times:

1. at least five guaranteed clinical-availability epochs before the terminal
   verification-only disclosure;
2. clinically consequential observations in at least two organ domains in
   addition to the circulation output itself;
3. at least two **distinct concurrent-process target candidates** that are
   source-supported as co-active in the same preterminal availability epoch.
   Each candidate must have its own independent source assertion and a
   trackable trajectory with at least two temporally separated source-supported
   witnesses.  Multiple observations, organs or assays generated by the same
   underlying process count once, not as duplicate process targets;
4. at least one performed action with a separately reported later response;
5. at least one explicitly examined/tested reliable negative finding;
6. at least one result whose sample/action occurrence precedes result
   availability;
7. a reported final diagnosis supported by a direct or convergent diagnostic
   basis rather than title assertion alone.

The extra-organ-domain count is not a proxy for process complexity: one
systemic process may produce abnormalities in several organs.  Before
selection, the screener therefore compiles a separate opaque concurrent-process
candidate packet from source assertions only.  This compilation is
model-blind and disease-name-blind: it may not read or receive a model pack,
runtime, oracle, expected diagnosis, terminal outcome or scoring output.  Its
public result contains only deterministic opaque candidate ids, the qualified
target count and content-addressed source references; it does not name a
disease or assert an oracle target.

`compile_opaque_concurrent_process_candidates.py` is the frozen offline
compiler and validator.  The screening manifest and evidence index must bind
the same exact packet.  The source auditor later verifies and seals that packet;
only the sealed packet may be used by the oracle adjudicator to define process
targets and by the post-replay scorer/auditor to verify coverage.  Neither raw
nor sealed complexity packets are evaluator inputs.  Fewer than two qualified
co-active candidates makes that case ineligible rather than forcing an
unreachable concurrent-process gate after deterministic selection.

All retrieved candidates are dispositioned.  If fewer than three are eligible,
the run stops `HARNESS_INCOMPLETE`; no bespoke third search is allowed.  Among
eligible candidates, selection is deterministic: compute

```text
SHA256(
  "NCF-PRIMARY-SELECTION-v1" + "\n" +
  frozen_query_contract_sha256 + "\n" +
  raw_ordered_identifier_projection_sha256 + "\n" +
  canonical_eligible_id_set_sha256 + "\n" +
  canonical_case_id
)
```

and select the lexicographically smallest digest.  The selector must be the
frozen `select_primary_holdout.py`, not a human choice.

The three binding hashes above are computed only from frozen Q1/Q2 semantics,
the exact ordered identifier projection recovered from the raw responses, and
the sorted evidence-qualified eligible identifier set.  Seal generation time,
retrieval time, JSON whitespace, file hashes containing such metadata, and all
other executor-controlled metadata are excluded from the winner preimage.  A
metadata-only rewrite therefore cannot grind the selection toward a preferred
case.

## 3. Immutable source and complete denominator

Before extraction, save immutable article HTML/XML/PDF and supplement snapshots
with URL, retrieval time, content type, byte count and SHA-256.  Every clinical
statement in prose, tables, figures and captions receives a source assertion id
and exact locator.  Duplicate renderings share an assertion/alternative-
representation group.  Narrative boilerplate may be non-rankable, but it
remains in the denominator.

**Non-mention is unknown.**  It is never `false`, `absent`, `normal`,
`not_tested`, or a reliable negative.  A rankable negative requires an explicit
source assertion, target/scope, adequate method/timing and reliability.  Phrases
such as “ruled out” are hypothesis/record-only statements unless their
underlying observations are independently extracted.

Author diagnoses, differential diagnoses, retrospective interpretations and
terminal outcomes are typed separately from observations.  They are never
rankable observations.  Raw finding and author interpretation are separate
source assertions.

## 4. Conservative availability time

Publication order is not clinical availability.  The ledger preserves:

```text
occurred/sample interval
result-generation interval
recorded interval
clinician-availability interval or partial-order constraints
certainty and source locator for each bound
```

Exact clock values are used only when reported.  Otherwise the harness derives
ordinal availability epochs from source-supported partial order.  Events in the
same reported batch remain in the same cut.  A fact is released at the first cut
where its **latest possible availability** is proved no later than that cut.  If
that cannot be established, it stays unavailable for stagewise ranking and is
carried as `availability_unknown`/epistemic evidence; no convenient timestamp is
invented.

`tools/compile_availability_epochs.py` is the frozen executable form of this
rule.  It accepts the typed availability ledger, releases an interval only at
its supported upper bound, keeps an entire reported batch on one cut, and
withholds unknown or unbounded partial-order events to measurement uncertainty.
The runtime never receives a pre-populated or guessed `available_at` from the
extractor.

Sampling, action start, result generation, chart recording and clinician
availability remain distinct.  A later response never moves backward to action
start.  The final published diagnosis and terminal outcome are verification
targets only.

At each cut the order is fixed:

1. reveal only newly guaranteed-available events;
2. recursively update and seal canonical state bytes/hash;
3. run all heads on those same bytes;
4. seal no-new-action/current-policy forecasts;
5. only then open the next cut.

The implementation of this sequence is itself frozen before case selection.
The combined pre-primary seal binds the exact bytes of
`tools/event_ledger_replay.py` and its test source.  The structural execution
evidence path is likewise fixed by binding `tools/structural_gate_harness.py`,
its test source, and both `tools/structural_gate_*.schema.json` output schemas.
It also binds the primary runtime replay executor and its input/output/replay-
seal schemas, the deterministic case-gate evaluator, its exact raw-runtime
integration test and report-candidate schemas, the case-gate evidence compiler, and the independent producer replay
verifier.  The runtime executor consumes exactly nine case-neutral classes:
the sanitized runtime ledger, sealed concept map, model pack, runtime, scoring
contract, protocol, oracle seal hash only, sanitized id/type/unit registry, and
the combined pre-primary seal.  Role-manifest/DAG verification remains an external
post-replay audit and is not silently added as a tenth executor input.
Only these case-blind generators, tests and output contracts are pre-primary
inputs.  No case-derived replay bundle, structural evidence object, or
structural result bundle is generated or bound by the pre-primary seal.

## 5. Role and packet isolation

Transport identifiers are not a free-text anonymization surface.  A presealed,
case-blind sanitizer/compiler assigns them and the validator independently
recomputes them; no role chooses an identifier payload.  The run id is exactly
`RUN-` plus the complete 64-lowercase-hex `payload_sha256` of the combined
pre-primary seal.  Event ids are `EV-00000001`, `EV-00000002`, ... in canonical
sanitized-ledger row order.  Action ids use `ACT-` plus the one-based,
zero-padded eight-decimal first-occurrence order; source-concept tokens use
`SC-` plus their first-occurrence order in the canonical sanitized ledger, and
the sealed concept-map rows must follow that same order exactly; alternative
groups use `ARG-` plus their first-occurrence order in that ledger.
Missing numbers, duplicates, arbitrary hashes, retained ids after reordering or
any other role-selected suffix are `HARNESS_INCOMPLETE`.  This transport-id
derivation does not grant the source auditor a new combined-seal input; the
external sanitizer/compiler and validator perform that binding.

Every role supplies a machine `role_execution_manifest.json` conforming to
`NCF-PRIMARY-ROLE-MANIFEST-1.1.0`.  It lists canonical relative, in-root,
non-symlink input/output paths with exact bytes, SHA-256, data class and schema
id; records case-identity exposure; and binds the exact prompt/command, tool
trace and parent packet as path/hash/byte objects.  Every role must consume and
produce **every** class in its frozen allowlists exactly once.  A structured,
content-addressed tool-access trace lists each actual read/write with operation,
artifact kind, path, hash, bytes, data class and schema id; the validator derives
`observed_data_classes` from that trace instead of trusting a self-attestation.
The trace must close exactly over the declared inputs, outputs, prompt and parent
packet, with no undeclared or forbidden access.  It also records network
requests separately.  The scout must record every HTTPS GET retrieval and is
restricted to the frozen NCBI host allowlist; every other role has an empty
network-request list and `network_access_detected=false`.

A `PRESEALED_ROOT` input is not any convenient in-root file.  It must have the
frozen canonical path and exact path/hash/byte tuple embedded in the one verified
`PRE_PRIMARY_HOLDOUT_SEAL.json` named by its producer.  A role-produced input
must equal an output row from its declared producer manifest, including the
producer-manifest path, hash **and byte count**.  Inputs, outputs and immutable
lineage artifacts may not overlap.  The complete eight-role manifest set must
instantiate the entire frozen producer-consumer DAG, in producer-before-consumer
time order, not merely an arbitrary acyclic subset.  Shared filesystem access is
not OS-level isolation, so missing lineage, a hollow/self-authored trace, an
unexplained input, or an incomplete role/DAG set is `HARNESS_INCOMPLETE`, not a
pass.

The evaluator's sanitized runtime ledger is the sole non-role input edge.  It
is **not** a presealed root and is no longer authored by the source auditor.
After the source auditor has sealed the event/availability ledgers and the
concept mapper has sealed the concept map, the frozen offline
`compile_evaluator_sanitized_runtime_ledger.py` executable consumes those three
artifacts, the frozen sanitized registry and the combined-seal reference.  It
emits the ledger plus a content-addressed assignment proof.  A separately
sealed verifier then re-executes that compiler in a fresh subprocess and binds
both outputs byte-for-byte.  The evaluator manifest must declare producer kind
`SEALED_EXECUTABLE_OUTPUT`, the exact frozen producer id, the proof reference
and the independent replay-verification reference.  The role validator checks
the proof's canonical logical output basename, binds the verification to the
ledger's actual run path, and independently repeats the exact dual-output fresh
replay against the sealed compiler/verifier/schema surface.  Proof and replay
verification are validator-only lineage metadata, not evaluator clinical
inputs.  Neither the evaluator nor the concept
mapper is thereby granted access to source text, identity or case values beyond
the compiler's sanitized ledger output.

| Role | May see | Must not see |
|---|---|---|
| scout | scope, search plan, exclusions, combined seal | model/runtime/registry/scores/oracle |
| screener | frozen search snapshot, immutable candidate-source snapshots/evidence index, exclusions | model/runtime/registry/scores/oracle/expected diagnosis |
| extractor | immutable selected source, extraction schema | model/runtime/registry/scores |
| source auditor | selected source, source inventory, raw event/availability ledgers, raw diagnosis-neutral mapper packet | model/runtime outputs/scores |
| concept mapper | **auditor-sealed** diagnosis-neutral mapper packet and sanitized id/type/unit registry | case id, values, chronology, hypotheses, diagnosis, outcome, likelihoods, priors, couplings, model pack/runtime output |
| oracle adjudicator | selected source, auditor-sealed source inventory/event/availability ledgers, sanitized process names/descriptions | model numeric parameters/model pack and all runtime outputs |
| evaluator | identity-neutral sanitized runtime ledger, sealed map, model/runtime/scoring rules, frozen protocol and combined seal, sanitized registry, oracle hash only | case identity/PMID/PMCID/DOI/title/source locator/source text, network, oracle contents, raw/sealed complexity packets, final diagnosis/outcome before all cut outputs are sealed |
| scorer/auditor | all sealed artifacts after replay, mapped-observation ledger, source-rich audited ledgers/reports and oracle contents | artifact modification; may emit only a failure-only `audit_report` inside the role DAG |

The eight-role DAG is sealed before any final gate/report decision.  The
presealed deterministic case-gate evaluator, gate-evidence compiler and final
scorer run **outside** that DAG over the complete eight-role manifest/closure.
Their `case_evaluation`, report candidate, report-consistency, scoring and final
result objects are external automated outputs, not self-authored role outputs.
This prevents a scorer role from producing an object that it must also audit.

The mapper packet contains only diagnosis-neutral source concept id,
definition, value type, unit, method class and reliability semantics.  Action
concepts are mapped in an analogous values/times-free packet.  Mapping output is
only `mapped_id`, `unmapped`, or typed ambiguity; the mapper cannot decide event
rankability or write likelihood weights.

The source auditor produces source-rich sealed inventory/event/availability
artifacts that retain provenance for the oracle and the post-replay scorer only.
The external frozen compiler—not any role—derives the separate
`evaluator_sanitized_runtime_ledger` conforming to
`ncf.evaluator-sanitized-runtime-ledger.v1`: opaque run/event/action ids and
opaque source-concept tokens, strictly typed values, a closed presealed unit
enum, non-negative case-relative observation/availability epoch ordinals,
reliability and action lifecycle.  Calendar dates are forbidden.
`OBSERVATION` rows carry only five closed tri-state source-evidence
qualifications (`explicit_assertion`, `target_scope`, `adequate_method`,
`adequate_timing`, `adequate_reliability`) plus a nullable opaque
alternative-representation group id; they may not carry an action lifecycle.
`ACTION`/`SUPPORT` rows must carry lifecycle but may not carry observation
qualification fields.  Their only author phases are `ORDERED`, `STARTED`,
`CONTINUED`, `DOSE_CHANGED`, `HELD`, `RESUMED`, `STOPPED`, and `COMPLETED`.
`WASHOUT` is never source-authored: it is derived after stop/completion by the
frozen runtime action-memory policy.  Dosing phases carry a canonical finite
non-negative normalized intensity bounded by the frozen model action's
`dose_reference`; the dose unit must equal the sealed action-registry unit
(currently null/unitless), so free clinical dose text or units are forbidden.
Action results are separate `OBSERVATION` events.  Categorical/action values use
a closed code enum rather than arbitrary strings.
It contains no PMID/PMCID/DOI/title/locator, article text, URL or reversible
source-result id.  Giving the evaluator the source-rich ledger is identity
leakage even if its manifest claims `case_identity_exposed=false`.

Before runtime consumption, a separate evidence-contract pass is mandatory for
every mapped observation.  The source auditor supplies only the five closed
source-evidence qualifications and opaque alternative group above.  The replay
executor—not the author—derives active supports at the observation epoch,
masking risk, conditioned-factor availability, rankability disposition, and
selected/suppressed alternative representations from the sealed lifecycle,
concept map and frozen model.  `FAILED/UNKNOWN` method, failed unit
normalization, `LOW/UNKNOWN` reliability, or a support-masked result without a
conditioned factor is withheld from `factor_messages`; it enters
`unexplained_observations(reason=unknown_measurement_condition)` and contributes
to or explicitly explains `measurement_uncertainty`.  Reliable negative
evidence is consumed only when explicit assertion, target scope, adequate
method, adequate timing and reliability are all true.  The primary evidence
tree must cross-check consumed, withheld and residualized source ids against
every factor message.

## 6. Independent oracle before runtime output

After source extraction/audit but before any primary runtime output, an
independent oracle adjudicator records and seals:

- the article-reported final diagnosis and evidence-strength grade;
- diagnosis-to-frozen-process correspondence using only sanitized process
  names/descriptions;
- expected concurrent processes and organ domains;
- decisive event ids and a decisive-cut definition based only on availability;
- directional positive/negative assertions and incompatible alternatives;
- clinically consequential event ids;
- later outcomes used only for verification.

The evaluator receives only the oracle hash, never its contents.  The oracle is
opened by the scorer only after all cut outputs and forecasts are sealed.  This
prevents choosing a decisive cut, target process or “important evidence” after
seeing model behavior.  A published diagnosis is not treated as biological
ground truth: the evidence-strength grade and unresolved alternatives remain in
the report.

## 7. Scoring and verdict boundary

`PRIMARY_HOLDOUT_SCORING_v1.json` is frozen and bound before case selection.
Case-specific directional assertions and the decisive cut are supplied only by
the independently sealed oracle, never by the evaluator.

The run is `HARNESS_INCOMPLETE` if source/availability truth cannot support the
minimum complex-case coverage.  It is `FAILED` with a classified reason if a
consequential fact is representable but incorrectly consumed/updated, if the
target process is not localized under the frozen rule, if future information
leaks, or if a hard gate fails.  A missing model concept/process is a
`MODEL_CONTENT` failure; unresolvable article timing is `DATA_EVIDENCE`;
observational treatment-effect ambiguity is `UNIDENTIFIABLE`, not an
architecture failure.

The only authoritative final aggregator is the frozen
`tools/final_primary_holdout_scorer.py` with
`schemas/primary_holdout_final_result.schema.json`.  It canonicalizes output to
the exact thirty gate ids and order in the frozen gate contract.  A missing,
duplicate, unknown or malformed gate row; missing evidence reference; or any
`NOT_EXECUTED`, `EVIDENCE_MISSING`, or `NOT_APPLICABLE` hard-gate result is
`HARNESS_INCOMPLETE`.  Once the evidence bundle is structurally complete, any
hard-gate `FAIL` is `FAILED`.  The same distinction applies to every frozen
complex real-case coverage item.  The sole positive path is all thirty hard
gates `PASS` **and** every complex real-case coverage item `PASS`.  A correct
published or runtime diagnosis is recorded but can never override either
classification.

An `evidence_ref` is never an unchecked string.  It is a canonical in-root
path plus SHA-256 **and byte count** to a `primary_gate_evidence` JSON object.
The scorer opens the file, rejects symlinks/path escape, verifies its exact
content reference, subject id, and claimed result, then independently rebuilds
the assertion result from source artifacts.  Every source artifact is itself
an exact canonical in-root, non-symlink `path + sha256 + bytes` reference.

Positive evidence must name an automated producer whose executable has the
exact content reference frozen in the verified combined pre-primary seal.  The
producer id, producer-output schema, and permitted gate/coverage subject must
match the frozen allowlist; a sealed generator for one subject cannot mint a
result for another.  Each assertion supplies a source-ref id, RFC 6901 JSON
pointer, claimed `observed` value, `expected` value, and deterministic
operator.  The scorer reopens the source, resolves the pointer, requires the
actual value to equal `observed`, and recomputes the operator.  An author-written
`passed: true` boolean has no evidentiary force and is schema-invalid.

`PASS` requires at least one recomputed assertion and all assertions true;
`FAIL` requires at least one recomputed assertion to be false.  The explicitly
identified independent scorer/auditor role may preserve a content-addressed
manual audit only to establish `FAIL`; it cannot mint `PASS`.  If a positive
gate cannot be established by an allowed sealed generator, the verdict is
`HARNESS_INCOMPLETE`, not a manually asserted success.  A fake path, wrong
hash/bytes, cross-gate artifact, unsealed producer, source-pointer mismatch, or
false assertion hidden behind `PASS` is likewise `HARNESS_INCOMPLETE`, never
positive.

Before case selection:

- architecture and wire hashes;
- gate v1.1 contract and seal;
- runtime and generic model seals;
- this protocol and machine contract;
- frozen scoring contract;
- final thirty-gate scorer, exact result schema and scorer test-source hash;
- content-addressed per-gate evidence schema;
- availability-epoch compiler, typed ledger schema and compiler test-source hash;
- protocol validator and its test-source hash;
- offline raw-search compiler/validator, exact-response schemas, and both test-source hashes;
- offline screening-evidence validator, its evidence schema and test-source hash;
- evaluator-sanitized-ledger compiler, compiler input/output schemas, assignment-
  proof schema and compiler test-source hash;
- independent evaluator-sanitized-ledger replay verifier, its dual-output replay-
  verification schema and verifier test-source hash;
- event-ledger replay generator and its test-source hash;
- structural-gate harness, its test-source hash, and its evidence/result schemas;
- selection algorithm/tool hash, selector test-source hash, role-manifest schema,
  and complete-role-manifest-set schema;
- combined pre-primary seal binding all of the above.

After selection and before replay:

- search snapshot and screening manifest;
- deterministic selection result;
- immutable source manifest/snapshots;
- complete source inventory and independent audit;
- diagnosis-neutral event ledger and conservative cut manifest;
- mapper packet, sanitized registry, concept map and role manifests;
- sealed oracle (contents hidden from evaluator);
- replay/evaluation input manifest.

Only after those artifacts are sealed may the primary sequential replay begin.
